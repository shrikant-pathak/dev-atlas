# Exercise Set — Problem Solving

## Easy
- [ ] Identify the sequence, selection, and iteration parts in this instruction: "For each item in the cart, if the price is over $50, apply a 10% discount."
- [ ] Draw (on paper or digitally) a simple flowchart for: "Check if a number is positive, negative, or zero."
- [ ] Write pseudocode for a function that returns the larger of two numbers.
- [ ] Name the three categories of bugs and give a one-sentence example of each.

---

## Medium
- [ ] Write pseudocode for an algorithm that counts how many vowels are in a given word.
- [ ] Compare two different algorithms for checking if a word is a palindrome — describe both approaches conceptually (no code needed).
- [ ] A function meant to return the sum of a list always returns `undefined`. Using the systematic debugging steps, describe how you'd investigate this.
- [ ] Draw a flowchart for a simple login check: input a password, check if it matches the stored one, output "Access Granted" or "Access Denied".

---

## Hard
- [ ] Write pseudocode for an algorithm that finds the second-largest number in a list, without sorting the list first.
- [ ] Explain why a logic error can be harder to find than a runtime error, using a specific example.
- [ ] Take a piece of buggy pseudocode (write one yourself, with an intentional logic flaw) and walk through the full 5-step debugging process to find and describe the fix.

---

## Bonus
- [ ] Research and briefly explain what "Big O notation" is used for, and why it matters when comparing two algorithms that both solve the same problem correctly.
