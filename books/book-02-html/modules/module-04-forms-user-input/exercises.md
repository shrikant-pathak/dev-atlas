# Exercise Set — Forms & User Input

## Easy
- [ ] Build a `<form>` with `action="/search"` and the correct `method` for a search bar.
- [ ] Write a properly labeled text input for "Full Name" using the `for`/`id` method.
- [ ] Write a `<select>` dropdown with 3 country options.
- [ ] Write a `<button>` with the correct `type` for a form-clearing action.

---

## Medium
- [ ] Build a radio button group for "Preferred Contact Method" (Email/Phone) using the same `name`, each properly labeled.
- [ ] Build a `<fieldset>` with `<legend>` grouping 3 checkboxes for "Interests".
- [ ] Write an email input with `required` and explain what happens if a user submits the form empty.
- [ ] Build a `<textarea>` for user feedback with a proper label and `rows` attribute.

---

## Hard
- [ ] Build a complete signup form: username (3-20 chars), email, password (min 8 chars), and a submit button — all properly labeled and validated.
- [ ] Explain, with a concrete example, why a hacker could bypass all your `required`/`pattern` attributes, and what that means for how you must build your backend later.
- [ ] Build an `<input>` + `<datalist>` combo suggesting 4 programming languages, while still allowing free text entry.
- [ ] Find and fix the bug: a `<button>` inside a `<form>` meant only to trigger a JavaScript function is unexpectedly submitting the form. Explain the fix.

---

## Bonus
- [ ] Research the `autofocus` and `autocomplete` attributes (not covered in depth in this module) and explain what each does.
