# Module 01 Interview Questions — Bootstrap Fundamentals

1. What is Bootstrap, and what problem does it solve compared to writing all your CSS by hand?
2. What changed in Bootstrap 5 regarding its JavaScript dependencies?
3. What are the two main ways to add Bootstrap to a project? When would you choose one over the other?
4. What is the difference between `bootstrap.bundle.min.js` and `bootstrap.min.js`?
5. Why is the viewport meta tag essential in any Bootstrap project?
6. In what order should your custom CSS and JS files be loaded relative to Bootstrap's own files, and why?
7. What is Reboot, and how does it differ from a typical CSS reset?
8. Does Bootstrap 5 support Internet Explorer? What are the implications of that for a real project?
9. Explain the two ways to control a Bootstrap component (e.g., a modal) — one without writing any JavaScript, and one with.
10. Why do tooltips and popovers require manual JavaScript initialization while modals and dropdowns don't?
11. What naming convention does Bootstrap use for its custom JavaScript events, and can you give an example?
12. If you were auditing a legacy project and found it was using Bootstrap 3, what practical differences would you expect compared to Bootstrap 5?
13. Why does Bootstrap namespace all of its data attributes with a "bs-" prefix?
14. Describe a real scenario where you'd need the programmatic JavaScript API instead of relying purely on data attributes.
15. What is Popper, and why does it matter for Bootstrap's JavaScript bundle?
